# Window 4: libraries by family of law, browsing in Typeset, and My Files

Brendan, 2026-09-14. Read `2026-09-14-legislative-xml-program.md` first,
decisions 11 and 12. This brief is your scope only. Starts once window 1
has committed the address scheme in `apps/web/docs/xml/schema.md`.

## What this window makes

The way a reader finds a Work and loads it. As Python has libraries and a
design project has a design library, the corpus organizes into libraries:
the Agricultural Law Library, the Housing Law Library, a session of
Congress, New York's code, a constitution. Sections overlap across families
and are distinct within them. A reader browses a library, filters and sorts
it, selects one Work and loads it in Typeset. The `/` command is the
keyboard door to the same libraries. And the reader's own copies live in
"My Files", not "Forks".

## What exists

The `Laws` table carries `law_name`, `law_type`, `chapter`, `title`,
`doc_type` per location; bills carry subjects (`Subjects`), policy areas
(`/policy-areas`), legislative subjects (`/legislative-subjects`), sessions
and committees. The workspace's data surface (`/workspace/data`, its folder
view in `components/create/folder-view.tsx`) browses bills as files in
folders; the sidebar's Forks folder and Duplicate to edit are in
`components/create/file-view.tsx` and the workspace shell. Window 2's
`expressions` index is the catalogue of what has been compiled; the library
reads it and falls back to `Laws` and `Bills` for what has not.

## Scope

1. **Families.** A first mapping from the corpus's own labels (`law_name`,
   `law_type`, subjects, policy areas) to families of law, as data in
   `lib/xml/families.ts`, editable by hand later. A Work may belong to more
   than one family.
2. **The Library surface in Typeset.** A view in `lib/typeset/views.ts`
   (slug `library`, label "Library") and a page at `/workspace/typeset/library`
   for when no bill is open: libraries as the top level; inside one, the
   Works as a browsable, filterable, sortable list (jurisdiction, kind,
   family, session or code, date, coverage), with a Work opening in the XML
   view. Reads the `expressions` index first and the source tables behind
   it.
3. **The `/` command.** In the editor and on the library page: `/119`,
   `/new-york-code`, `/new-york-constitution`, `/arkansas-agricultural-law`,
   `/6644`, resolving through the address scheme to a library or a Work.
   Replaces window 1's stub.
4. **My Files.** Rename the Forks folder to My Files everywhere a reader
   sees it: the sidebar, the file view, the duplicate flow, page titles. The
   tables keep their names. Leave the seam for window 5's true fork to land
   in the same folder.

## Not in scope

The fork itself, amendments, citations, the compiler, storage.

## Done means

session and a state's code, filters and sorts, loads a Work into the XML
view; the sidebar says My Files. Committed on the branch by path. Report at
